# 图床、CDN 与商家独立域名后续任务

> 状态：Backlog，暂不进入当前开发与部署范围  
> 目标：为智贸云后续的 TB 级商品图片、全球前台访问和商家自有完整域名提供可执行的技术任务清单。

## 1. 总体原则

- 商品图片离开业务服务器磁盘，统一进入 S3 兼容对象存储。
- 后端只保存对象键和图片元数据，不在 PostgreSQL 中保存图片二进制。
- 存储实现保持供应商中立，业务代码不能直接依赖某一家厂商的专有 URL。
- 商家之间必须按 `tenant_id` 隔离对象、用量、域名和缓存。
- CDN 只缓存公开且可安全共享的内容；登录、权限、库存和商家后台数据不得进入公共缓存。
- 所有缓存键必须包含商家、完整域名、语言、分页、筛选和排序等实际影响响应的维度，禁止跨商家串数据。
- 前端发布、图片替换和商品更新都必须支持明确的缓存失效策略。
- 本文只记录后续方案，不改变当前本地或生产环境。

## 2. 任务一：商品图床

### 2.1 目标

建立支持 TB 级容量、多租户隔离、直接上传、自动压缩、用量统计和后续迁移的商品图片存储层。当前优先候选为：

- Backblaze B2：适合长期多 TB 存储，作为成本优先候选。
- Cloudflare R2：接入和 Cloudflare 生态更直接，作为简单部署候选。

最终实施前重新核对价格、服务区域、SLA、API 限制和付款条件。应用层统一使用 S3 兼容接口，使 B2、R2、MinIO 之间可以迁移。

### 2.2 数据与对象结构

建议对象键使用不可变、可追踪的结构：

```text
tenants/{tenant_id}/products/{product_id}/{content_hash}/master.webp
tenants/{tenant_id}/products/{product_id}/{content_hash}/card.webp
tenants/{tenant_id}/products/{product_id}/{content_hash}/detail.webp
```

新增图片资产记录，至少保存：

- `tenant_id`
- `product_id`
- 对象存储供应商和 bucket
- master、card、detail 对象键
- 内容哈希
- MIME 类型
- 原始及处理后尺寸
- 文件字节数
- 上传、处理和扫描状态
- 创建时间、删除时间和最后引用时间

数据库中不保存带供应商域名的永久 URL。展示地址应由对象键和当前存储配置动态生成，便于以后迁移。

### 2.3 上传与处理流程

1. 后端校验商家权限、剩余额度和商品归属。
2. 后端签发短时、单对象、限定 MIME 的上传凭证。
3. 浏览器直接上传对象存储，不让大文件经过 FastAPI 业务进程。
4. 上传完成后创建处理任务。
5. 处理任务校验真实文件类型、像素尺寸和文件完整性。
6. 清除 EXIF、GPS 和无关元数据。
7. 生成预定义的商品卡片图和详情图。
8. 成功后原子更新商品图片引用；失败时保留可重试状态和明确错误。

初期不依赖按请求动态生成图片规格，避免在大量 SKU 和大量尺寸组合下产生不可控的转换费用。推荐先固定：

- `card`：商品列表使用的小尺寸 WebP。
- `detail`：商品详情使用的中等尺寸 WebP。
- `master`：限制最大边长并压缩后的母版，用于以后重新生成规格。

原始未压缩文件是否长期保留，需要在实施前根据客户合同、重新处理需求和存储成本单独决定。

### 2.4 多租户、额度与安全

- 每个商家单独统计图片数量、逻辑用量和实际存储字节数。
- 套餐可以限制总容量、单商品图片数、单文件大小和像素上限。
- 上传凭证只能写入当前商家的固定前缀，不能由浏览器任意指定对象键。
- 同时校验扩展名、Content-Type 和文件魔数。
- 防止解压炸弹、超大像素图片、伪造图片和路径穿越。
- 私有母版与公开展示图分离；只有公开展示规格允许通过公开图片域名访问。
- 删除商品时先解除引用并进入延迟清理，避免误删仍被其他记录使用的对象。
- 定时清理未完成上传、孤儿对象、失败处理中间文件和过期旧版本。
- 图片删除、替换、迁移和额度变更写入审计日志。

### 2.5 迁移任务

- 盘点当前本地 volume、MinIO 和数据库中的全部图片引用。
- 建立可重复执行、可断点续传、可校验哈希的迁移命令。
- 迁移期间兼容旧地址和新地址，避免一次切换导致历史图片失效。
- 完成对象数量、总字节数和抽样内容哈希核对后再切换读取路径。
- 保留明确的回滚窗口，回滚期结束后再清理旧存储。

### 2.6 验收标准

- 两个商家不能读取、覆盖或删除对方的私有图片资产。
- 大文件上传不占用业务 API 的主要带宽和 Worker。
- 列表图和详情图尺寸、格式、方向和透明度正确。
- 上传失败、处理失败和额度超限都有可理解的前台提示。
- 可以按商家查看图片数量、总容量、当月新增量和失败任务。
- 迁移脚本重复执行不会产生重复引用或破坏已完成对象。
- 更换 S3 endpoint 后，业务模型和商品接口不需要重写。

## 3. 任务二：CDN 与页面打开速度

### 3.1 目标

CDN 的首要目标不是代替后端，而是把 React 构建产物、字体、公开图片和可安全缓存的商家前台数据放到更接近用户的位置。FastAPI、PostgreSQL、登录与商家后台继续运行在业务服务器。

建议后续拓扑：

```text
浏览器
  ├─ HTML / JS / CSS / 字体 ── Cloudflare 静态资产
  ├─ 公开商家前台 API ────── Cloudflare 短缓存 ── FastAPI
  ├─ 登录及商家后台 API ──── 不缓存 ─────────── FastAPI
  └─ 商品展示图片 ────────── Cloudflare 缓存 ── B2 或 R2
```

### 3.2 前端静态资产

候选方案为 Cloudflare Workers Static Assets 或 Cloudflare Pages。只部署 Vite 的构建产物，不在边缘部署数据库和现有 FastAPI。

缓存策略必须区分入口 HTML 和带哈希静态文件：

```http
# index.html
Cache-Control: no-cache, must-revalidate

# /assets/ 下带内容哈希的 JS、CSS、字体和图标
Cache-Control: public, max-age=31536000, immutable
```

实施任务：

- 建立独立的前端构建和边缘发布流程。
- 保持 SPA 路由回退，直接访问商品详情和后台子路由不能返回 404。
- 发布必须原子化，不能先删除旧文件再上传新文件。
- 保留最近版本的旧分包，或为动态模块加载失败提供一次安全刷新恢复。
- 前端发布失败时能够回退到上一份可用构建。
- 验证 CSP、字体、Source Map 和环境变量不会因为迁移而泄露或失效。

### 3.3 公开商品 API 短缓存

只考虑缓存无需登录即可访问、对所有访客内容一致的 GET 接口，例如：

- 商家公开资料
- 一级、二级分类
- 商品分页列表
- 商品详情
- 公共语言翻译结果

建议初始策略为短缓存，并使用后台更新：

```http
Cache-Control: public, s-maxage=60, stale-while-revalidate=300
```

实际 TTL 在上线前压测决定。缓存键至少包含：

- 完整 Host
- `tenant_id` 或稳定商家标识
- 语言
- 币种
- 页码和每页数量
- 一级、二级分类
- 搜索词
- 排序和展示模式中会影响响应的参数

以下内容必须明确返回 `Cache-Control: private, no-store`：

- 登录、刷新令牌和账户资料
- 商家控制台接口
- 权限和成员信息
- 购物车、询盘和报价写操作
- 采购成本、供应商和库存变动
- 平台管理员接口

### 3.4 缓存失效

- 商品、分类、标签或商家公开资料变更后，主动清理对应公开地址。
- 批量导入完成后统一失效，避免每行导入都触发一次清理。
- 图片使用内容哈希新地址，替换图片时不覆盖旧对象。
- 缓存失效失败必须可重试，并保留事件记录。
- 失效策略不得使用“清空全站缓存”作为常规操作。

### 3.5 监控与验收

监控指标：

- HTML、JS、CSS 的 TTFB 和下载耗时
- LCP、INP、CLS 等真实用户指标
- 前台商品 API 的 p50、p95、p99
- CDN HIT、MISS、BYPASS 比例
- 回源请求量和回源错误率
- 每次发布后的静态资源 404 和动态模块加载失败
- 各语言、各商家、各地区的首屏加载时间

验收标准：

- 静态资源从 Cloudflare 边缘返回，并带有正确缓存响应头。
- `index.html` 发布后能及时更新，旧会话不会大面积遇到分包 404。
- 登录和后台响应无法从公共 CDN 缓存中读取。
- 公开 API 的缓存键不会在商家、域名、语言或筛选条件之间串用。
- 关闭 CDN 或回滚边缘发布后，业务服务器仍能继续提供服务。

## 4. 任务三：每个商家的独立完整域名

### 4.1 域名层级定义

后续需要明确支持三种入口，它们不是同一功能：

| 类型 | 示例 | 用途 |
|---|---|---|
| 当前兼容路径 | `4everapi.top/qingwan` | 保留兼容和回退 |
| 平台默认子域名 | `qingwan.4everapi.top` | 商家无需自备域名即可使用 |
| 商家自有完整域名 | `catalog.customer.com` 或 `customer.com` | 商家品牌化正式入口 |

本任务的核心是第三种：让商家绑定自己拥有的完整域名，而不是只修改平台路径中的商家名。

### 4.2 商家操作流程

1. 商家在控制台录入完整域名。
2. 系统规范化域名并检查是否已被其他租户使用。
3. 系统生成 DNS 所有权验证记录和接入记录。
4. 商家在自己的 DNS 服务商添加 TXT、CNAME、ALIAS/ANAME 或平台要求的记录。
5. 系统异步检查 DNS 验证结果。
6. 验证成功后自动申请并续期 TLS 证书。
7. 域名状态变为可用，商家可以设置为主要域名。
8. 旧路径和默认子域名按配置跳转到主要域名。

需要在界面展示：

- 待验证
- DNS 配置错误
- 证书签发中
- 已生效
- 续期异常
- 已停用

每个错误状态都应给出实际检测结果和修复方法，不能只显示“绑定失败”。

### 4.3 平台接入方案

优先调研 Cloudflare for SaaS Custom Hostnames，用于批量接入客户域名、证书签发和边缘路由。实施前验证其最新价格、套餐限制、根域名支持方式和证书验证要求。

应用层需要增加域名提供商适配层，至少封装：

- 创建自定义 hostname
- 查询 DNS 验证状态
- 查询证书状态
- 重新触发验证
- 停用和删除 hostname

这样未来更换 Cloudflare 方案时，不需要重写商家、权限和数据库模型。

### 4.4 数据模型

建议新增 `tenant_domains`，至少包含：

- `id`
- `tenant_id`
- 规范化后的 `hostname`
- 是否主要域名
- 是否平台默认域名
- DNS 验证方式和验证令牌
- DNS 验证状态
- TLS 状态
- 路由状态
- 最近检查时间
- 最近错误代码和可展示错误信息
- 创建、验证、启用、停用时间

`hostname` 必须全局唯一。域名比较需要：

- 转换为小写
- 去除结尾的点
- 统一 IDNA/Punycode 表示
- 拒绝端口、路径、协议和通配符输入

### 4.5 Host 路由与安全

- 每个公开请求先根据可信的规范化 Host 查找租户。
- 不能继续只依赖 URL 中的 `tenantSlug` 判断商家。
- 未验证、已停用或未知 Host 返回安全的未绑定页面，不能回退到任意默认商家。
- 禁止绑定平台保留域名、登录域名、API 域名和图片域名。
- 验证成功前不允许域名进入正式路由，防止域名抢占。
- 租户停用、域名删除或所有权丢失时立即停止路由。
- CDN 缓存键必须包含完整 Host，避免两个客户的同路径商品页面互相污染。
- 管理后台和平台登录继续使用平台主域名，不向客户域名共享后台 Cookie。
- 商家自有域名只承载公开商品前台和公开商品详情。

### 4.6 SEO、跳转与多语言

- 每个商家只能设置一个主要域名。
- 非主要入口使用 301/308 跳转到主要域名，避免重复收录。
- canonical、Open Graph、站点地图和 robots 内容使用当前商家的主要域名。
- 多语言页面生成正确的 `hreflang` 和语言地址。
- 分享链接、报价中的前台链接和二维码使用主要域名。
- 主要域名变更需要保留旧域名跳转窗口，并记录审计日志。

### 4.7 验收标准

- 商家可以按照界面提示独立完成域名验证和接入。
- 子域名和根域名的支持范围、DNS 要求和失败原因清晰。
- TLS 自动签发、续期和异常重试无需人工登录服务器。
- 相同完整域名不能同时绑定两个租户。
- 修改 Host 不能访问其他商家的数据。
- 商家停用后，其自有域名不能继续展示历史商品数据。
- 默认平台入口、自有域名和主要域名跳转行为符合配置。
- 自有域名下的分类、分页、详情、多语言、购物车和报价入口行为一致。

## 5. 推荐实施顺序

1. 建立 S3 兼容存储抽象和图片资产数据模型。
2. 接入正式图床并迁移现有图片。
3. 将前端构建产物迁移到 Cloudflare 静态资产。
4. 为公开商品 API 增加可验证的短缓存和失效事件。
5. 建立基于 Host 的租户解析。
6. 接入平台默认子域名。
7. 完成客户自有完整域名、DNS 验证和自动 TLS。
8. 加入完整监控、用量计费、告警和回滚演练。

## 6. 实施前需要确认的产品决策

- 商品原始未压缩图片是否必须永久保留。
- 每个套餐包含的图片容量、单商品图片数和超额计费方式。
- 图床最终选择 B2、R2，还是母版与公开展示图分层存储。
- 平台默认地址继续使用路径，还是升级为商家子域名。
- 自有完整域名是所有套餐功能，还是付费增值功能。
- 是否允许绑定根域名，还是第一阶段只支持 `shop.customer.com` 等子域名。
- 商家更换主要域名时，旧域名保留跳转的时间。
- 自有域名是否只承载公开商品前台，不承载商家后台和平台登录。
