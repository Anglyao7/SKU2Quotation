# 商品翻译记忆库

## 当前实施范围

商品翻译继续使用平台配置的 Qwen Batch 或实时供应商。Translation Memory 位于供应商请求之前，按商家、源语言和目标语言隔离；更换供应商不会抹掉已完成译文。Redis 只是短期热缓存，PostgreSQL 条目不再因 60 天未访问而自动删除。

查找顺序：

1. 人工微调和当前有效语言包的译文（保持现有实体级优先级）。
2. 相同原文的持久记忆；Unicode NFC 和无意义的水平空白差异视为同一原文，但保留大小写、数字、单位、标点、`/` 和换行边界。
3. 数字模板记忆。只有其余文字完全相同、旧译文保留了每个原始数值、没有型号编码或单位换算歧义时，才替换数值并保存为新的精确记忆。
4. 未命中或检查失败的文本交给当前配置的供应商翻译，并在验证后写入记忆。

例如 `猫碗 10 cm` → `Cat bowl 10 cm` 可以安全复用为 `猫碗 12 cm` → `Cat bowl 12 cm`。`猫碗` 改成 `狗碗`、`10 cm` 被译成英寸、数字被拼写成单词、型号变化等情况都不能仅靠相似度复用，必须请求 Qwen 或人工确认。这样可以省掉安全的重复调用，而不会把语义不同的商品错译到前台。

现有全量重译按钮仍表示主动重新请求供应商；增量和自动翻译优先复用记忆。发布语言包与翻译记忆分离，旧版语言包在新结果通过检查并发布前继续服务访客。

## 上线顺序

1. 应用迁移 `20260927_0148`。迁移只增加可空的匹配索引列，不在发布窗口内扫描并改写全部旧译文。
2. 在 API 运行环境逐商家执行 `python -m scripts.backfill_translation_memory_indexes TENANT_UUID`（本地虚拟环境用 `.venv/bin/python`）。脚本每 500 条提交一次，可安全中断和重跑；旧译文在回填前仍可按原文精确命中。
3. 用一批真实商品记录精确命中、数字模板命中、供应商请求和 QA 失败数量，再决定是否扩展为术语表、字段类别路由或人工审核工作台。

翻译记忆不跨商家共享商品内容；人工微调目前是实体级覆盖，不会自动扩散到其他商品。将来若增加可跨商品复用的术语，必须由管理员明确批准并维护独立的术语表。
